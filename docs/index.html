Two kinds of button

A prompt, or a whole pipeline

Deterministic operations stay deterministic. An agent should never decide on its own whether the right branch merged or whether production deploy is authorized.

Agent button one prompt

Runs a single principal agent prompt with inputs, permissions, a timeout, and success criteria.

  • Research a topic and write a cited blog post
  • Read Jira activity and prepare a weekly report
  • Review the current pull request
  • Turn a folder of notes into a PowerPoint

Workflow button deterministic + agent

Combines commands, agent steps, approvals, waits, and validation with pinned variables.

  • Validate repo → merge pinned SHA → trigger Jenkins → wait → QA
  • Retrieve Jira → summarize → generate DOCX → upload
  • Research → outline → approve → write → export
  • Every step's evidence recorded to an audit log
What it owns

Small, deterministic, in your control

The daemon compiles a button into an execution plan, starts the agent, streams events, enforces boundaries, records evidence, and stops the process tree when needed.

▤

No-code builder

Fill in a name, plain-language instructions, questions to ask, and a schedule. YAML lives behind an Advanced toggle for developers.

⧉

Native agent config

Adapters normalize orchestration and events, not features. Each agent keeps its skills, MCP servers, plugins, and subscription login.

◷

Schedules that survive restarts

Cron with timezones, overlap and missed-run policies. A SQLite lease guarantees no double-fires across ticks or reboots.

✋

Approvals after preflight

The approval screen shows resolved facts — pinned SHA, files changed, tests passed — not intentions.

◈

Evidence, not vibes

Success requires artifacts on disk, exit codes, Jenkins status, and QA checks — never the agent's word that it worked.

⌦

Clean cancellation

Every run gets its own process group. Cancel kills the whole tree, so no orphaned agent or MCP subprocesses remain.

⌨

TUI, web & CLI

An Apple-quiet terminal dashboard, a browser dashboard, a web TUI over a pty, and abtn on the command line — one daemon behind them.

⛭

Secret references

secret://keychain/… resolves only at the integration boundary. Tokens never touch prompts, transcripts, or the database.

◱

Dry run everything

Compile and preview every step's resolved plan without a single side effect. Then run it for real.

Quick start

Running in under a minute

Requires Bun. First boot seeds example buttons so the dashboard isn't empty.

# clone & install
git clone https://github.com/cskwork/agent-button
cd agent-button && bun install

# the local control daemon (unix socket, SQLite, scheduler)
bun run daemon

# pick a surface
bun run web     # http://127.0.0.1:4173 — dashboard + web TUI
bun run tui     # terminal dashboard
bun run cli list # abtn list / run / logs / approve
